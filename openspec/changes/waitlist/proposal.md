# Change: Лист ожидания

## Why

Популярные события заполняются за часы. Сейчас при исчерпании вместимости типа билета регистрация отвечает 400 «No places left», и участник уходит. Когда кто-то отменяет регистрацию, место освобождается, но узнать об этом можно только перезаходя на страницу. Организатор теряет участников, участники теряют места.

## What Changes

- Для типа билета организатор может включить лист ожидания.
- При исчерпании вместимости регистрация на такой тип билета ставит участника в очередь вместо отказа.
- При освобождении места первый в очереди автоматически переводится в регистрацию и получает письмо; участник, попавший в очередь, получает письмо о постановке.
- Участник с учётной записью видит свою позицию в «Мои регистрации» и может выйти из очереди.
- Организатор видит очередь в списке участников.

Затронутые capability: `registration` (MODIFIED «Ограничение мест», ADDED «Лист ожидания», «Выход из листа ожидания»), `events` (ADDED «Лист ожидания у типа билета»), `notifications` (ADDED два письма), `participant-cabinet` (MODIFIED «Мои регистрации»).

FR-09.3 «Список ожидания (waitlist)» в `spec/phase-b-business-architecture.md` переходит из «Won't (след. фаза)» в Must; раздел 3.2 Phase A обновляется.

## Out of Scope

- Платные типы билетов: автоматический перевод из очереди невозможен без реальной оплаты, а оплата в первой версии — заглушка. Лист ожидания доступен только для типов билетов с ценой 0. Платные — после внедрения платежей.
- Предложение места с подтверждением и таймером (offer/expire). Выбран автоматический перевод; см. design.md.
- Ручное управление очередью организатором (перемещение, приоритеты).
- Уведомления SMS.

## Impact

- Схема БД: новая колонка `ticket_types.waitlist_enabled`, новая таблица `waitlist_entries` — скрипт `012_waitlist.sql`.
- API: `POST /api/v1/events/{id}/registrations` получает новый ответ 202 при постановке в очередь; новые endpoints для выхода из очереди и просмотра очереди организатором; `GET /api/v1/me/registrations` дополняется записями очереди. Существующие ответы 201/400/402/404/409 не меняются.
- Код: `RegistrationsService` (постановка в очередь, продвижение при отмене), `AdminService` (продвижение при аннулировании), `EmailTemplates` (два шаблона), frontend (кабинет организатора, «Мои регистрации», форма регистрации).
- Документация: `spec/phase-b-business-architecture.md` FR-09.3, `spec/phase-c-information-systems-architecture.md` модель и API, `docs/testing-checklist.md`.
