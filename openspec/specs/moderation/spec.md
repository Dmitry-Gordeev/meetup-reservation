# Moderation Specification

## Purpose

Администрирование платформы (BC-09): постмодерация событий, блокировка организаторов и участников, просмотр пользователей. Источник: FR-08.1–FR-08.3, `AdminController`, `AdminService`. Управление категориями описано в `categories`.

## Requirements

### Requirement: Доступ администратора

Система SHALL предоставлять endpoints `/api/v1/admin/*` только пользователям с ролью `admin` (политика `AdminOnly`).

#### Scenario: Организатор обращается к админке

- **WHEN** пользователь без роли `admin` вызывает любой endpoint `/api/v1/admin/*`
- **THEN** ответ 403

### Requirement: Постмодерация событий

Система SHALL публиковать события сразу и позволять администратору заблокировать активное событие через `PATCH /api/v1/admin/events/{id}/block` и разблокировать через `.../unblock`; список событий для модерации — `GET /api/v1/admin/events`.

#### Scenario: Блокировка события

- **WHEN** администратор блокирует событие со статусом `active`
- **THEN** статус `blocked`, событие скрыто из каталога и доступно по прямой ссылке с пометкой

#### Scenario: Разблокировка

- **WHEN** администратор разблокирует событие со статусом `blocked`
- **THEN** статус `active`, событие снова в каталоге

#### Scenario: Блокировка отменённого события

- **WHEN** событие уже `cancelled`
- **THEN** блокировка не применяется, ответ 404

### Requirement: Блокировка организатора

Система SHALL при блокировке организатора через `PATCH /api/v1/admin/organizers/{id}/block` устанавливать `is_blocked`, отменять все его активные события и уведомлять их участников; разблокировка снимает `is_blocked`, отменённые события не восстанавливаются.

#### Scenario: Блокировка организатора с событиями

- **WHEN** администратор блокирует организатора
- **THEN** вход организатору запрещён, его события `active` переведены в `cancelled`, участники получили письма

#### Scenario: Разблокировка организатора

- **WHEN** администратор разблокирует организатора
- **THEN** организатор может войти и создавать новые события; ранее отменённые остаются отменёнными

### Requirement: Блокировка участника

Система SHALL при блокировке пользователя через `PATCH /api/v1/admin/users/{id}/block` запрещать вход, аннулировать все его активные регистрации и уведомлять организаторов затронутых событий.

#### Scenario: Блокировка участника с регистрациями

- **WHEN** администратор блокирует участника
- **THEN** его регистрации `registered` и `checked_in` переведены в `cancelled`, организаторы уведомлены

### Requirement: Просмотр пользователей

Система SHALL отдавать администратору список пользователей с email, признаком блокировки и ролями через `GET /api/v1/admin/users`.

#### Scenario: Список пользователей

- **WHEN** администратор запрашивает список
- **THEN** возвращаются все пользователи с ролями и статусом блокировки
