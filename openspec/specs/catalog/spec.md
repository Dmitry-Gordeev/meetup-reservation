# Catalog Specification

## Purpose

Публичный каталог событий (BC-04): список, фильтрация по категориям, сортировка, cursor-пагинация, страница организатора, отображение статусов. Источник: FR-03, `EventsService.GetEventsListAsync`, `GetOrganizerEventsAsync`.

## Requirements

### Requirement: Публичный каталог

Система SHALL отдавать через `GET /api/v1/events` без авторизации публичные события со статусом, отличным от `blocked`, включая отменённые и прошедшие с соответствующей пометкой.

#### Scenario: Гость открывает каталог

- **WHEN** неавторизованный посетитель запрашивает список
- **THEN** возвращаются публичные незаблокированные события с названием, датами, местом, признаком онлайн, статусом и названием организатора

#### Scenario: Заблокированное событие

- **WHEN** событие имеет статус `blocked`
- **THEN** его нет в списке, но оно доступно по прямой ссылке с пометкой

### Requirement: Фильтрация по категориям

Система SHALL фильтровать каталог параметром `categoryIds` по логике OR: событие попадает в выборку, если имеет хотя бы одну из выбранных категорий; архивные категории участвуют в фильтрации.

#### Scenario: Две категории

- **WHEN** передано `categoryIds=1,2`
- **THEN** в выборке события с категорией 1, с категорией 2 и с обеими

### Requirement: Сортировка

Система SHALL поддерживать параметр `sortBy` со значениями `startAt` (по дате проведения, по возрастанию) и `createdAt` (по дате создания, новые первыми); значение по умолчанию — `startAt`.

#### Scenario: Сортировка по дате создания

- **WHEN** `sortBy=createdAt`
- **THEN** первым идёт последнее созданное событие

### Requirement: Пагинация

Система SHALL возвращать не более `limit` событий (1–100) и `nextCursor` для следующей страницы; курсор кодирует значение сортировки и идентификатор последнего элемента.

#### Scenario: Следующая страница

- **WHEN** клиент передаёт `cursor` из предыдущего ответа с теми же фильтрами и сортировкой
- **THEN** возвращаются следующие события без повторов и пропусков

#### Scenario: Последняя страница

- **WHEN** событий меньше или равно `limit`
- **THEN** `nextCursor` равен `null`

### Requirement: Страница организатора

Система SHALL отдавать публичные незаблокированные события организатора через `GET /api/v1/organizers/{id}/events`.

#### Scenario: Несуществующий организатор

- **WHEN** организатора с таким id нет
- **THEN** ответ 404

### Requirement: Отображение статуса

Система SHALL сообщать клиенту статус события так, чтобы интерфейс мог показать пометки «отменено» и «завершено»; завершённым считается событие, у которого `end_at` в прошлом.

#### Scenario: Прошедшее событие

- **WHEN** `end_at` раньше текущего времени
- **THEN** событие показано в каталоге с пометкой «завершено», регистрация недоступна
